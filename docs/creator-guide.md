# SCENE 작품 제작·편집 가이드

2026-11-22 · scene-stream/11 · 소스/ZIP 1.4.0

기본 다섯 작품을 편집용으로 불러오거나 새 작품을 만들 수 있다. 제작 설정과 실행 설정은 같은 `NarrativeDefinition`을 사용한다. 그래프 화면용 모형을 별도로 실행하지 않는다.

## 제작 흐름

1. **프로필:** 제목·소개·장르·플레이어 역할·표지·권장 모델·답변 길이.
2. **세계관·인물:** 세계의 규칙과 현재 갈등, 등장인물별 이름·역할·성격·말투·외모. 장면마다 대화 화자를 지정한다.
3. **시작 설정:** 여러 시작점, 시작 장면·프롤로그·첫 대사·스탯 초기값. 시작 시각과 한 턴당 경과 분을 지정한다. 초기값을 비우면 스탯 기본값을 사용한다.
4. **상태·스탯:** HP·산소·소지금 등 자유 이름, 최소·최대·초기값·단위·공개 여부. 선택형 상태는 `정상, 손상, 위독`처럼 입력하며 내부 값은0,1,2다. 조건부 INFO 문구도 구성한다. 표시 조건은 위에서부터 처음 충족되는 문구를 사용하며 위/아래 버튼으로 순서를 바꾼다.
5. **장면·분기:** 장면 상황·장소·화자·목표·최소 장면 턴, 추천 후보, 행동의 실행 의미·일회성 여부·효과·시간, 다음 장면 전이와 조건, 진행/완료 사건.
6. **미디어:** 기존 이미지 선택 또는PNG/JPEG/WebP 업로드. 브라우저는 긴 변1400px 이내 WebP로 변환하고 최종700KB 이하로 전송한다. 인물·감정·장면·스탯 조건·이번 턴의 사건·우선순위·한 번만·재표시 간격을 지정한다.
7. **설정집:** 추가 사실, 키워드와 공개 조건. 키워드는 현재 입력과 최근4개 메시지에서 문맥을 찾는 힌트다. 비밀 보호는 수치 조건으로 구성한다.
8. **엔딩:** 복수 최종 엔딩과 계속 대화할 수 있는 중간 진행을 구분한다. 엔딩의 장면·수치 조건과 우선순위를 설정한다.
9. **테스트·등록:** 정의·ID 참조·초기값·조건 범위를 검사하고 온톨로지 연결을 확인한다. 규칙 시뮬레이션 또는 실제 모델 테스트 채팅 후 작품을 등록한다.

조건 편집기의 한 묶음은 **모두 충족(AND)**이다. OR 분기는 같은 도착지로 가는 별도 전이를 추가해 표현한다. 임의 코드·JavaScript·SQL·수식을 실행하는 편집기는 아니다. 숫자 효과는 등록한 고정 변화량이며 LLM이 임의의 변화량을 반환하지 않는다. 문장으로 입력한 실행 의미는 자유 입력을 분류하는 기준이며, 실행의 게이트·수치 범위·최소 턴·일회성 조건은 코드로 검사한다.

규칙 시뮬레이션은 LLM과 저장 없이 같은 엔진으로 진행한다. 상태를 초기화하고 행동·전이를 눌러 게이트, HP, 다음 장면과 엔딩을 확인한다. 연결 검사는 조건을 모두 고려한 도달 가능성의 수학적 증명은 아니다. 실제 대화 품질은 테스트 채팅에서 확인해야 한다.

## 원본·초안·등록 버전·대화

- **불러오기:** 원본의 전체 장면·조건·엔딩을 복사한다. 원본 기본 작품과 기존 사용자 대화는 수정하지 않는다.
- **로컬 임시 저장:** 입력마다 이 브라우저에 복원 가능한 편집 내용을 남긴다.
- **초안 저장:** 소유자별 DB에 미완성 정의도 저장한다. 초안은 대화 라이브러리에 공개하지 않는다. 저장 버전이 충돌하면409로 막는다.
- **작품 등록:** 검사한 초안에서 새 ID의 작품 버전을 만든다. 내 브라우저의 라이브러리에 추가된다. 이후 원본이나 초안을 수정해도 등록 버전은 바뀌지 않는다.
- **테스트 채팅:** 검사한 초안으로 별도 작품 스냅샷과 새 회차를 만든다. 실제 사용자의 기존 회차에 테스트 입력을 넣지 않는다.
- **회차 고정:** 작품·선택한 시작점·초기값·프롤로그·세계 정의를 회차에 고정한다. 다음 번 초안 수정과 다른 시작점은 해당 회차를 바꾸지 않는다.

현재 공개 데모는 로그인 계정 대신 브라우저의 서명된 세션 쿠키로 소유자를 구분한다. 사용자 작품·초안·업로드는 브라우저별 비공개이며 다른 고객의 목록에 등록하지 않는다. 기존처럼 데이터는 임시 데모 용도로 약7일 보관한다. 장기 운영에서는 계정 기반 소유권과 보존 정책을 추가해야 한다.

## 미디어와 스트리밍

미디어의 게이트는 확정된 이번 턴의 상태로 평가한다. 사건 이미지는 해당 사건이 이번 턴에 적용됐을 때만 후보가 된다. 감정 이미지는 현재 허용된 후보 중 대사 모델이 선택한 표정 또는 기존 장면의 기본 분위기에 맞춰 표시한다. 자연어 사용 상황은 모델에 주는 지침이며, 강제 공개 제한에는 장면·사건·수치 조건을 사용한다. 내부 표정 접두사는 스트림에서 제거하고 대사만 즉시 전달한다. 별도 LLM 이미지 판정 호출은 없다. 한 턴 최대 한 이미지를 선택하며 우선순위·인물·쿨다운·일회성을 다시 검사한다.

대화와 함께 선택한 미디어 참조를 저장하므로 새로고침에서도 같은 그림을 본다. 공개 플레이 응답에 아직 선택되지 않은 미디어 전체 목록을 보내지 않는다. 업로드는 클라우드의 비공개 S3에 소유자별 저장하고, 세션이 있는 `/api/media/:id`로 읽는다. 로컬은 별도 파일 저장소를 쓴다. SVG·외부 URL·data URL은 등록하지 않는다.

**GPU 생성은 연결하지 않았다.** 제작 API는 비활성 상태를 반환한다. 추후 영상랩의 생성 작업 어댑터를 붙여 생성물 선택 → 미디어 등록으로 연결할 수 있다. 이번 배포에 GPU 인스턴스·작업 큐·추론 비용은 추가하지 않았다. 정지 이미지 편집·자동 표정 선택과 H3/Wan의 영상 생성은 별도 기능이다.

## API와 저장

- `GET /api/creator`: 내 초안, 불러올 원본 목록, GPU 연결 상태.
- `GET /api/creator/template`: 기본 작품 초안.
- `GET /api/creator/sources/:id`: 기본 작품 또는 내가 소유한 작품·초안 정의.
- `POST /api/creator/drafts`: `{ id?, revision?, sourceId?, document }`.
- `POST /api/creator/validate`: `{ document }`.
- `POST /api/creator/simulate`: `{ document, startId?, state?, actionId?, transitionId? }`.
- `POST /api/creator/media`: `{ type, data }`, data는base64 이미지.
- `POST /api/creator/publish`, `/test`: `{ draftId, revision, startId? }`.
- `POST /api/episodes`: 기존 `{ story }`와 함께 선택적인 `startId`를 받는다.

모든 쓰기는 기존 same-origin 검사와 서명된 세션 범위를 사용한다. 클라우드는 DynamoDB, 이미지 파일은 S3, 확정 회차의 그래프 투영은 DynamoDB Streams→Lambda 경로를 그대로 사용한다. 로컬은 SQLite WAL과 파일 저장소를 사용한다.

현재 제작 한도는 장면24개, 인물12명, 스탯16개, 행동32개, 전이40개, 엔딩10개, 시작점8개, 미디어40개다. 회차24턴 한도와 모델별 출력 편차는 유지된다. 제작 폼의 안내 문구는 한국어이며 플레이 대화의 영어·일본어 설정은 계속 사용할 수 있다.

## 검증

`tests/scene-creator.test.ts`에서 기본 작품 전체 복사, 범위/참조 오류, 여러 시작점과 선택형 상태, 미디어 조건·일회성·소유권, 화자와 설정집 검색, 초안 버전 충돌, 등록 불변성, 편집한 스타워즈의 HP 적용·재조회, 접두사 분할 스트리밍을 검사한다.

최종 소스48개 검사와 타입 검사, 독립 ZIP41개 검사·빌드·CDK 합성이 통과했다.

공개 배포 scene-stream/11에서 편집한 스타워즈로 Sonnet5.5를8턴 실행했다. HP80→90, 조건부 INFO, 이번 사건의 업로드 이미지, 우회·출항·여섯 척 호송·합류·인계 엔딩을 확인했다. 매 턴의 재조회가 커밋 응답과 같았고 비동기 그래프가 최종8버전에 수렴하면서 Media 노드를 포함했다. 다른 시작점은 HP30과 선택형 ‘손상’ 상태를 사용했고 다른 소유자의 미디어·초안 접근은404였다. 이 API 검증의 임시 회차만 삭제했다.

Chrome에서는 원본 스타워즈 불러오기 → 최소3턴·연료40 이상 조건·자유 스탯 ‘선체 HP’·점검 시+10·업로드 이미지의 HP90 이상 조건을 편집 → 초안 저장 → 새 작품 등록 → 규칙 시뮬레이션 → 실제 Sonnet 테스트 채팅을 확인했다. 브라우저4턴에서 궤도와 호송 장면으로 이동하고 HP90·피난선6척·추천이 유지됐다. 새로고침과 별도 편집 탭에서 저장한 초안 복원, 정의 JSON 내보내기도 확인했다. 기존 기본 작품과 사용자 원래 대화는 수정하지 않았다.

비동기 그래프 투영의 조건 검사와 다음 턴 잠금이 잠깐 충돌하는 DynamoDB TransactionConflictException에는 동일한 버전·토큰 조건을 유지하면서 제한된 지수 지연 재시도를 적용했다. 상태 조건을 느슨하게 하거나 LLM을 다시 호출하는 방식이 아니다.

테스트용 작품은 실제 회차 목록에서 다시 열 수 있지만 작품 탐색과 원본 불러오기 목록에서는 제외해 등록 작품과 중복 노출하지 않는다.

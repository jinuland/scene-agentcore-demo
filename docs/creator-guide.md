# 간편 이야기 제작

기본 화면은 **이야기 설명 → 캐릭터·미디어 → 확인·테스트**의 세 단계입니다. 기존 작품도 이 화면에서 불러옵니다. 기술적인 ID·비공개 진행 플래그·그래프 조건은 기본 화면에서 입력하지 않습니다.

1. 세계관과 인물, 시작과 전개를 말로 적습니다.
2. “연료는 80에서 시작하며 우회할 때 20 감소한다. 연료가 0이면 표류한다”처럼 선택의 결과를 적습니다. 원하는 성공·실패 결말도 적습니다.
3. **Opus로 계획하고 이야기 구성하기**를 누르면 Opus5.5가 계획을 세우고 Sonnet5.5 작업자들이 공통 설정과 장면·연결을 나누어 작성합니다. 진행과 완료 결과를 오른쪽에서 확인할 수 있습니다. 서버가 스키마와 그래프 참조를 검사합니다. 제안이 실패하면 기존 초안은 유지됩니다.
4. 장면·수치·결말 요약을 읽고 **이 구성 적용**을 누릅니다. 검증은 형식과 연결의 유효성을 확인하며 작가 의도의 완전한 해석을 보장하지 않으므로 테스트 채팅에서 분기를 확인합니다.
5. 캐릭터와 감정(기쁨·슬픔·분노·걱정 등)을 골라 이미지를 올립니다. 해당 인물이 그 감정으로 반응할 때 등록한 미디어를 사용합니다. Qwen-Image-2.1로 정면·측면·후면을 담은 캐릭터 시트 한 장과 참조 기반 감정 이미지를 만들 수도 있습니다. 개별 기준 모습 5장은 선택 사항입니다. GPU 연결 여부는 화면에 표시됩니다.
6. 시작 문장과 필요한 초기 수치를 바꾸고 테스트하거나 등록합니다. **세부 규칙을 직접 수정하고 싶어요** 아래에 기존 고급 편집이 있습니다.

‘초기값 사용’은 **해당 작품에 구성된 값**을 뜻합니다. 다른 작품이 같은 연료·신뢰도 스탯을 상속하는 의미가 아닙니다. 새 작품은 AI 구성 단계에서 설명에 맞춰 스탯을 만듭니다. 채팅 중에 스탯 정의를 임의로 생성하지 않습니다.

추천은 현재 조건을 만족하는 작가 선택지를 우선하며 세 개까지 표시합니다. 후보가 부족하면 현재 가능한 다른 행동과 목표·주변 위험을 확인하는 질문을 추가합니다. 잠긴 전이나 완료한 일회성 행동을 열지 않습니다. 끝난 회차에는 추천을 표시하지 않습니다.

배포된 `scene-stream/12`에서 새 빵집 설명을 AI로 구성해 ‘밀가루 재고’와 ‘손님 만족도’가 생성되는 것을 확인했다. 테스트 채팅에서 재고20→15, 추천3개, 대사 스트리밍, 새로고침 후 동일 상태를 확인했고, 별도의 스타워즈 회차는 연료0에서 표류 엔딩으로 종료됐다. 소스와 독립 ZIP의 관련 검사45개, 타입 검사, 빌드와 AWS 프로필을 사용한 CDK 합성이 통과했다.

관찰된 한계: 빵집 테스트에서 확정 재고는15였지만 생성 대사는10으로 잘못 말했다. 상태창·저장·분기 판정은 확정값15를 사용한다. 대사 속 수치 표현을 확정 상태에 일치시키는 보강은 남아 있다. 제작 AI가 해석한 세부 증감과 결말 조건도 적용 전 요약과 테스트로 확인한다.

AI 제작은 채팅과 별도인 명시적인 요청입니다. Bedrock 사용량이 발생하며 기존 API 일일 한도를 공유합니다. 기존 단일 생성 API는100초 상한이지만 기본 화면은 저장 가능한 작업 대기열을 사용합니다. 실패한 단계의 재시도와 변경되지 않은 완료 결과 재사용을 지원합니다. [진행 화면·실행 구조·비용과 복원](authoring-orchestration.md)을 참고하세요. 제안은 적용 전까지 초안을 바꾸지 않습니다. 이 제작 경로는 웹 Lambda → Bedrock이며 플레이 대화는 기존 AgentCore Runtime 경로를 유지합니다. 기존 미디어 조건과 설정집·상태창·진행 사건은 보존하며 참조가 깨지면 적용하지 않습니다.

## 대화로 작품을 다듬는 제작 보조

오른쪽 **제작 보조 채팅**은 Claude Opus 5.5를 사용합니다. 왼쪽의 아직 저장하지 않은 내용도 읽고 장면·스탯·엔딩 수정안을 제안합니다. 예를 들어 “여섯 장면과 초기값을 유지하고 빠진 엔딩 구간을 찾아줘”라고 요청할 수 있습니다. **설정에 적용**은 자연어 입력을 바꾸고, **적용 후 이야기 생성**은 이어서 Sonnet 5.5 구성기를 실행합니다. 생성된 장면·규칙도 요약을 검토한 뒤 적용합니다. 저장과 작품 등록은 별도입니다.

실제 MCP 서버와 클라이언트가 요청마다 인메모리 전송으로 연결됩니다. `read_story_settings`는 현재 폼을 읽고, `check_ending_coverage`는 정수 스탯의 경계에서 엔딩 누락·중복을 검사하며, `propose_story_settings`는 변경 전후가 있는 제안만 만듭니다. 폼을 수정한 뒤 오래된 제안을 적용하면 덮어쓰지 않고 다시 요청하도록 안내합니다. 경계 검사는 최종 장면의 수치 조건 검사이며 모든 장면의 도달 가능성을 증명하지 않습니다.

**웹 검색 사용**을 켜면 MCP `web_search`가 Amazon Nova 2 Lite의 웹 grounding 도구를 사용합니다. 출처 링크를 답변 아래에 유지합니다. 공식 자료와 검색 요약에도 오류가 있을 수 있으므로 원작 사실과 창작 설정을 구분해 검토합니다. 검색 자료는 설정 변경 권한이나 실행 지시로 취급하지 않습니다. 이 경로는 별도 검색 API 키가 필요 없으며, CDK가 Nova 모델 호출과 `amazon.nova_grounding`의 `bedrock:InvokeTool` 권한을 설정합니다. Nova 검색은 미국 버지니아 리전의 US inference profile을 사용합니다.

Opus는 adaptive thinking/medium을 사용합니다. 이는 필요한 내부 추론을 모델이 정하고 중간 정도의 노력을 쓰는 옵션입니다. 추론 원문은 화면이나 채팅 저장에 노출하지 않습니다. 한 답변당 최대 다섯 모델 라운드, MCP 도구 여덟 번, 웹 검색 두 번, 총210초(3분30초)로 제한하며 자동 유료 재시도는 없습니다. 작품별 제작 대화·검색 출처·MCP 도구 입력/결과·수정 제안·설정 적용 기록을 서버에 저장하며 브라우저에는 최근12개 메시지도 임시 보관합니다. 다음 요청은 서버에서 최근10개 메시지와 이전 대화·적용 설정 발췌(최대28000자)를 복원해 참고합니다. 모든 과거 원문을 매번 모델에 그대로 보내지는 않습니다. 전체 원문과 도구 기록은 제작 이력 내보내기에서 확인할 수 있습니다. 호출은 기존 제작 일일 한도를 공유하고, 여러 모델 라운드와 검색은 별도 Bedrock 사용량을 발생시킵니다.

# SCENE 작품 제작·편집 가이드

2026-11-22 · scene-stream/11 · 소스/ZIP 1.4.0

기본 다섯 작품을 편집용으로 불러오거나 새 작품을 만들 수 있다. 제작 설정과 실행 설정은 같은 `NarrativeDefinition`을 사용한다. 그래프 화면용 모형을 별도로 실행하지 않는다.

## 제작 흐름

1. **프로필:** 제목·소개·장르·플레이어 역할·표지·권장 모델·답변 길이.
2. **세계관·인물:** 세계의 규칙과 현재 갈등, 등장인물별 이름·역할·성격·말투·외모. 장면마다 대화 화자를 지정한다.
3. **시작 설정:** 여러 시작점, 시작 장면·프롤로그·첫 대사·스탯 초기값. 시작 시각과 한 턴당 경과 분을 지정한다. 초기값을 비우면 스탯 기본값을 사용한다.
4. **상태·스탯:** HP·산소·소지금 등 자유 이름, 최소·최대·초기값·단위·공개 여부. 선택형 상태는 `정상, 손상, 위독`처럼 입력하며 내부 값은0,1,2다. 조건부 INFO 문구도 구성한다. 표시 조건은 위에서부터 처음 충족되는 문구를 사용하며 위/아래 버튼으로 순서를 바꾼다.
5. **장면·분기:** 장면 상황·장소·화자·목표·최소 장면 턴, 추천 후보, 행동의 실행 의미·일회성 여부·효과·시간, 다음 장면 전이와 조건, 진행/완료 사건.
6. **미디어:** 기존 이미지 선택 또는PNG/JPEG/WebP 업로드. 브라우저는 긴 변1400px 이내 WebP로 변환하고 최종700KB 이하로 전송한다. 인물·감정·장면·스탯 조건·이번 턴의 사건·우선순위·한 번만·재표시 간격을 지정한다.
7. **설정집:** 추가 사실, 키워드와 공개 조건. 키워드는 현재 입력과 최근4개 메시지에서 문맥을 찾는 힌트다. 비밀 보호는 수치 조건으로 구성한다.
8. **엔딩:** 복수 최종 엔딩과 계속 대화할 수 있는 중간 진행을 구분한다. 엔딩의 장면·수치 조건과 우선순위를 설정한다.
9. **테스트·등록:** 정의·ID 참조·초기값·조건 범위를 검사하고 온톨로지 연결을 확인한다. 규칙 시뮬레이션 또는 실제 모델 테스트 채팅 후 작품을 등록한다.

조건 편집기의 한 묶음은 **모두 충족(AND)**이다. OR 분기는 같은 도착지로 가는 별도 전이를 추가해 표현한다. 임의 코드·JavaScript·SQL·수식을 실행하는 편집기는 아니다. 숫자 효과는 등록한 고정 변화량이며 LLM이 임의의 변화량을 반환하지 않는다. 문장으로 입력한 실행 의미는 자유 입력을 분류하는 기준이며, 실행의 게이트·수치 범위·최소 턴·일회성 조건은 코드로 검사한다.

규칙 시뮬레이션은 LLM과 저장 없이 같은 엔진으로 진행한다. 상태를 초기화하고 행동·전이를 눌러 게이트, HP, 다음 장면과 엔딩을 확인한다. 연결 검사는 조건을 모두 고려한 도달 가능성의 수학적 증명은 아니다. 실제 대화 품질은 테스트 채팅에서 확인해야 한다.

## 원본·초안·등록 버전·대화

- **불러오기:** 원본의 전체 장면·조건·엔딩을 복사한다. 원본 기본 작품과 기존 사용자 대화는 수정하지 않는다.
- **로컬 임시 저장:** 입력마다 이 브라우저에 복원 가능한 편집 내용을 남긴다.
- **초안 저장:** 소유자별 DB에 미완성 정의도 저장한다. 초안은 대화 라이브러리에 공개하지 않는다. 저장 버전이 충돌하면409로 막는다.
- **공개 게시:** 검사한 초안에서 새 ID의 고정 작품 버전을 만들고 공개 목록에 추가한다. 로그인 없이 다른 방문자도 작품을 열고 각자의 대화를 시작한다. 이후 초안 수정은 게시 버전에 영향을 주지 않는다. 테스트 채팅은 비공개다.
- **테스트 채팅:** 검사한 초안으로 별도 작품 스냅샷과 새 회차를 만든다. 실제 사용자의 기존 회차에 테스트 입력을 넣지 않는다.
- **회차 고정:** 작품·선택한 시작점·초기값·프롤로그·세계 정의를 회차에 고정한다. 다음 번 초안 수정과 다른 시작점은 해당 회차를 바꾸지 않는다.

현재 공개 데모는 로그인 없이 접속하며, 브라우저의 서명된 익명 세션 쿠키로 초안과 대화 소유자를 구분한다. 공개 게시한 작품은 모두의 작품 탐색에 표시한다. 일반 공개 게시에는 초안·제작 보조 대화·개인 회차·제작용 참조 시트를 포함하지 않는다. 작가가 별도로 공개 초안을 공유한 경우에만 제작 설명과 캐릭터 참조 이미지를 함께 제공한다. 공개 작품 정의는 별도 카탈로그에 저장하고 실제 플레이에서 사용하는 이미지만 공개용 사본으로 복사한다. 이미지 응답은 해당 공개 작품의 파일 목록에 포함된 경로만 허용한다. S3 버킷은 비공개 상태를 유지한다. 개인 회차·초안은 약7일, 개인 이미지·작업 파일은 약8일 보관하며, 공개 작품과 공개 이미지 사본에는 그 임시 삭제 정책을 적용하지 않는다.

## 미디어와 스트리밍

미디어의 게이트는 확정된 이번 턴의 상태로 평가한다. 사건 이미지는 해당 사건이 이번 턴에 적용됐을 때만 후보가 된다. 감정 이미지는 현재 허용된 후보 중 대사 모델이 선택한 표정 또는 기존 장면의 기본 분위기에 맞춰 표시한다. 자연어 사용 상황은 모델에 주는 지침이며, 강제 공개 제한에는 장면·사건·수치 조건을 사용한다. 내부 표정 접두사는 스트림에서 제거하고 대사만 즉시 전달한다. 별도 LLM 이미지 판정 호출은 없다. 한 턴 최대 한 이미지를 선택하며 우선순위·인물·쿨다운·일회성을 다시 검사한다.

대화와 함께 선택한 미디어 참조를 저장하므로 새로고침에서도 같은 그림을 본다. 공개 플레이 응답에 아직 선택되지 않은 미디어 전체 목록을 보내지 않는다. 업로드는 클라우드의 비공개 S3에 소유자별 저장하고, 세션이 있는 `/api/media/:id`로 읽는다. 로컬은 별도 파일 저장소를 쓴다. SVG·외부 URL·data URL은 등록하지 않는다.

**GPU 모델은 Qwen-Image-2.1을 선택했습니다.** 첨부 실험(2026-11-18)의 ArcFace 얼굴 코사인 유사도 평균은 Qwen0.870(40장), H3 짧은 프롬프트0.659(20장), 긴 묘사0.664(20장)입니다. 사람 사진 네 명을 변형한 실험이며, 코사인 점수를 동일인 정확도 백분율로 해석하거나 동화·애니·후면의 동일성을 보증하지 않습니다. 한글 정확 문구는 H3 긴 묘사35/48, Qwen26/48로 H3가 높았지만 이 데모는 캐릭터 동일성을 우선합니다. 대사와 상태창 글자는 웹 UI로 표시합니다.

기본값은 **캐릭터 시트 한 장**입니다. 2048×1024 캔버스에 정면·측면·후면을 한 번 생성하고, 원본 시트와 세 부분을 잘라 저장합니다. 네 개 파일이 생겨도 GPU 생성은 한 번이며 자르기는 추가 추론이 아닙니다. 장면 생성에는 잘라 둔 정면을 참조하고, 필요한 경우 다른 인물의 참조도 함께 사용합니다. 개별 기준 모습 5장 옵션은 정면을 먼저 만들고 그 정면으로 왼쪽·오른쪽·후면·45도를 각각 생성합니다. 기존에 만든 개별 이미지는 자동 재생성하지 않습니다.

[Qwen 공식 예제](https://github.com/QwenLM/Qwen-Image-2.1#panorama-and-storyboard)도 3방향 캐릭터 참조에서 스토리보드를 생성합니다. 한 장에 여러 뷰를 넣으면 각 뷰의 유효 해상도는 줄고, 방향별 외모가 다르거나 경계에서 잘릴 수 있습니다. 세밀한 단독 컷이 필요할 때만 개별 이미지를 추가하세요. 생성 횟수5→1을 비용80% 절감으로 해석하지 않습니다. [Comfy 공식 설명](https://github.com/Comfy-Org/docs/blob/main/tutorials/image/qwen/qwen-image-2-1.mdx#resolution)처럼 해상도·참조 크기·단계 수도 계산량에 영향을 줍니다. 2026-11-23 같은 공유 GPU에서 참조가 있는 QA 캐릭터 한 명의 요청 등록→저장 완료는 시트82.3초, 기존 개별5장224.4초였습니다. 각각 한 번의 관측이며 큐 대기·모델 준비를 포함하므로 모델 추론 시간이나 월 비용 비교로 쓰지 않습니다.

모델의 고정 revision, seed, 참조 이미지, 캐릭터·감정 정보를 결과와 함께 저장합니다. BF16,40단계를 사용하며 기존 다른 모델의4단계 설정이나 Turbo를 임의로 쓰지 않습니다.

**캐릭터 완료 후 장면·감정 이미지 자동 생성**을 켜면 제작 모델이 각 장면에 어울리는 서로 다른 감정 두 개와 등장인물 참조를 계획합니다. 서버에 계획과 의존 관계를 저장하고 캐릭터 이미지가 실제 저장된 뒤 장면 작업을 큐에 넣습니다. 브라우저를 닫아도 등록된 작업은 이어집니다. 다시 열면 작업 상태와 이미지를 복원합니다. 완료한 이미지는 왼쪽 갤러리와 진행 카드에 표시되며 장면·인물·감정·공개 조건이 미디어 규칙에 연결됩니다. 현재 장면 또는 감정이 다르면 해당 이미지는 선택되지 않습니다. 생성 완료 후 초안을 저장하고 새 테스트 회차에서 확인하세요. 이미 열린 회차는 생성 당시 작품 버전을 유지합니다.

업로드하지 않은 빈 이미지 칸과 아직 생성 중인 미디어 자리표시는 대화 이미지로 선택하지 않습니다. 파일 생성·저장 상태와 브라우저 표시 상태는 구분합니다. 갤러리는 동시에 최대3개 파일을 불러오고 일시적인 로딩 실패는3회 재시도합니다. 이후에는 명시적인 파일 로딩 오류와 다시 불러오기 버튼을 표시합니다. 이 재시도는 GPU를 재호출하지 않습니다. 장면 계획은 같은 요청 번호로 재조회해도 추가 모델 호출 없이 기존 계획을 돌려주며, 실패한 계획은 사용자가 다시 시작할 수 있습니다. 작품 한도는 이미지120개, 작업80개, 미디어 규칙80개입니다.

GPU 작업자는 별도 Python 프로세스로 비공개 S3 작업 대기열을 읽고 저장합니다. 웹 화면은4초마다 실제 진행 단계와 완료 이미지를 조회합니다. 기존 GPU 공유 잠금을 사용하며 다른 추론 작업을 강제로 종료하지 않습니다. CDK는 GPU 인스턴스나 모델 가중치를 만들거나 내려받지 않습니다. 모델이 준비된 기존 GPU, Diffusers의 `QwenImage21Pipeline`, 실행 계정, S3 권한이 필요합니다. ZIP에는 작업자·설정·설치 도구가 포함되며 모델 가중치는 포함되지 않습니다. 일반 배포는 GPU가 꺼져 있고 명시적으로 연결할 때만 활성화합니다.

~~~sh
# 먼저 GPU 역할에 이 데모의 S3 경로 권한을 부여합니다. 값은 자신의 환경으로 바꾸세요.
npm run deploy -- --profile customer-demo -c sceneGpuRole=YOUR_GPU_ROLE
python3 scripts/deploy-scene-gpu.py --profile customer-demo --region ap-northeast-2 --instance-id YOUR_EXISTING_GPU --bucket YOUR_CREATOR_MEDIA_BUCKET --python /opt/scene-studio/.venv/bin/python --user ubuntu
# 실제 이미지 생성 확인 후 웹 화면에서 활성화합니다.
npm run deploy -- --profile customer-demo -c sceneGpuRole=YOUR_GPU_ROLE -c sceneGpuEnabled=true
~~~

GPU 작업자는 준비된 `/opt/scene-studio` 실행 환경과 공유 잠금 모듈을 사용합니다. 다른 환경에서는 경로와 잠금 어댑터를 맞춰야 합니다. [공식 Qwen 모델 사용법](https://github.com/QwenLM/Qwen-Image-2.1) 및 `examples/agentcore-character-demo/gpu/model.json`에서 고정 모델 revision과 설정을 확인할 수 있습니다.

## API와 저장

- `GET /api/creator`: 내 초안, 불러올 원본 목록, GPU 연결 상태.
- `GET /api/creator/template`: 기본 작품 초안.
- `GET /api/creator/sources/:id`: 기본 작품 또는 내가 소유한 작품·초안 정의.
- `POST /api/creator/drafts`: `{ id?, revision?, sourceId?, document }`.
- `POST /api/creator/validate`: `{ document }`.
- `POST /api/creator/simulate`: `{ document, startId?, state?, actionId?, transitionId? }`.
- `POST /api/creator/media`: `{ type, data }`, data는base64 이미지.
- `POST /api/creator/publish`, `/test`: `{ draftId, revision, startId? }`.
- `POST /api/episodes`: 기존 `{ story }`와 함께 선택적인 `startId`를 받는다.

모든 쓰기는 기존 same-origin 검사와 서명된 세션 범위를 사용한다. 클라우드는 DynamoDB, 이미지 파일은 S3, 확정 회차의 그래프 투영은 DynamoDB Streams→Lambda 경로를 그대로 사용한다. 로컬은 SQLite WAL과 파일 저장소를 사용한다.

현재 제작 한도는 장면24개, 인물12명, 스탯16개, 행동32개, 전이40개, 엔딩10개, 시작점8개, 미디어40개다. 회차24턴 한도와 모델별 출력 편차는 유지된다. 제작 폼의 안내 문구는 한국어이며 플레이 대화의 영어·일본어 설정은 계속 사용할 수 있다.

## 검증

`tests/scene-creator.test.ts`에서 기본 작품 전체 복사, 범위/참조 오류, 여러 시작점과 선택형 상태, 미디어 조건·일회성·소유권, 화자와 설정집 검색, 초안 버전 충돌, 등록 불변성, 편집한 스타워즈의 HP 적용·재조회, 접두사 분할 스트리밍을 검사한다.

이전 구조화 편집 버전에서는 소스48개·독립 ZIP41개 검사가 통과했다. 간편 제작 버전의 검증은 배포 결과를 참고한다.

공개 배포 scene-stream/11에서 편집한 스타워즈로 Sonnet5.5를8턴 실행했다. HP80→90, 조건부 INFO, 이번 사건의 업로드 이미지, 우회·출항·여섯 척 호송·합류·인계 엔딩을 확인했다. 매 턴의 재조회가 커밋 응답과 같았고 비동기 그래프가 최종8버전에 수렴하면서 Media 노드를 포함했다. 다른 시작점은 HP30과 선택형 ‘손상’ 상태를 사용했고 다른 소유자의 미디어·초안 접근은404였다. 이 API 검증의 임시 회차만 삭제했다.

Chrome에서는 원본 스타워즈 불러오기 → 최소3턴·연료40 이상 조건·자유 스탯 ‘선체 HP’·점검 시+10·업로드 이미지의 HP90 이상 조건을 편집 → 초안 저장 → 새 작품 등록 → 규칙 시뮬레이션 → 실제 Sonnet 테스트 채팅을 확인했다. 브라우저4턴에서 궤도와 호송 장면으로 이동하고 HP90·피난선6척·추천이 유지됐다. 새로고침과 별도 편집 탭에서 저장한 초안 복원, 정의 JSON 내보내기도 확인했다. 기존 기본 작품과 사용자 원래 대화는 수정하지 않았다.

비동기 그래프 투영의 조건 검사와 다음 턴 잠금이 잠깐 충돌하는 DynamoDB TransactionConflictException에는 동일한 버전·토큰 조건을 유지하면서 제한된 지수 지연 재시도를 적용했다. 상태 조건을 느슨하게 하거나 LLM을 다시 호출하는 방식이 아니다.

테스트용 작품은 실제 회차 목록에서 다시 열 수 있지만 작품 탐색과 원본 불러오기 목록에서는 제외해 등록 작품과 중복 노출하지 않는다.

### 초안 다시 열기 · 1.9.1

상단의 단일 **초안·작품 선택**에서 **내가 저장한 초안 / 공개 초안 / 등록된 작품**을 구분해 고르고 **선택한 항목 열기**를 누릅니다. 별도의 저장한 초안 선택창은 없습니다. 내 초안은 제목과 버전을 표시하고 이어서 편집하며, 공개 초안·등록된 작품은 원본을 유지하는 내 사본으로 불러옵니다. 저장 직후 해당 초안이 선택됩니다. 초안 저장은 작품 공개 등록과 별개입니다. 저장 중에는 버튼을 비활성화하고 진행을 표시합니다. 쓰기가 성공한 뒤 목록 조회만 실패한 경우에도 저장 완료 상태와 저장한 초안을 유지합니다.

### 이미지 생성 진행 · 1.9.2

제작 보조 채팅 아래에 이미지 생성 진행 패널을 둡니다. 새 작업 등록 시 패널로 한 번 이동하고, 진행 중에는 강조 테두리와 실제 작업별 진행 막대·완료/생성 중/대기 개수를 보여 줍니다. 캐릭터 기준 모습 생성 버튼 아래에서도 해당 인물의 작업을 확인할 수 있습니다. 진행 조회마다 화면을 이동시키지 않습니다. 진행 중 작업을 복원하면 패널을 다시 안내하며, ‘이미지 생성 진행 보기’ 버튼으로 돌아올 수 있습니다. 완료 작업은 별도로 접어 표시합니다.

### 표지·프롤로그와 이미지 비율

새 작품은 시작 장면의 완료된 장면 이미지를 표지와 프롤로그에 자동 연결합니다. 사건이나 스탯 조건으로 잠긴 이미지는 도입 표지 후보에서 제외합니다. 캐릭터·미디어의 ‘프롤로그 이미지 선택’에서 직접 선택으로 바꾸면 제작자가 고른 표지를 유지합니다. 이 연결은 저장된 이미지를 재사용하며 별도 GPU 추론을 하지 않습니다. 대화와 프롤로그 이미지는 원본 비율로 표시해 위·아래를 자르지 않습니다.

### 공개 게시 API

`POST /api/creator/publish`에 `visibility: "public"`을 보내면 공개 카탈로그와 미디어 사본을 함께 만든다. 제작 도구의 공개 게시 버튼이 이 옵션을 사용한다. 기존 API 호환을 위해 옵션 생략은 이전의 개인 등록 동작을 유지한다. 이미 개인 등록한 작품은 `POST /api/creator/publications`에 `{storyId}`를 보내 같은 작품 링크로 공개 전환할 수 있다. 본인 소유의 정식 등록 버전만 전환하며 테스트 회차용 버전과 타인의 초안은 거절한다. 같은 등록 버전을 반복 요청하면 기존 공개 사본을 반환한다. 공개는 공통 작품에 대한 것이며 방문자의 대화·스탯·기억은 브라우저별 독립 회차에 저장한다.


### 누구나 불러오는 공개 초안

어린왕자 공개 작품의 **공개 초안 불러오기**를 누르거나 제작 도구의 **공개 초안 · 어린왕자의 모험**을 선택하면 장면6개·엔딩5개·스탯·작가 설명·캐릭터 참조 및 장면 이미지가 들어 있는 사본을 자신의 익명 세션에 저장한다. 공유 원본은 수정하지 않는다. 이미지도 방문자 소유 저장소로 복사하므로 새 장면 생성 시 참조할 수 있다. 불러오기 자체는 모델/GPU를 호출하지 않으며, 자동 장면 생성은 꺼진 상태로 시작한다.

`GET /api/creator/templates/:id`는 공개 제작 정의를 읽는다. `POST /api/creator/import-template`에 `{storyId}`를 보내면 이미지 사본과 새 개인 초안을 만들고 `{id, revision, sourceId, document}`를 반환한다. 작가가 자신의 정식 등록 버전을 명시적으로 공유하려면 `POST /api/creator/public-templates`에 `{storyId}`를 보낸다. 작업ID·생성 작업 상태·제작 보조 대화·플레이 대화는 공유하지 않는다. 공개 초안과 이미지에는 임시 삭제 정책을 적용하지 않으며, 방문자가 불러온 개인 사본은 기존 개인 초안 보관 정책을 따른다.


상단 **어린왕자 예제**도 배포에 저장된 공개 초안을 우선 불러오므로 캐릭터 기준35장·장면/감정12장이 포함된다. 공개 초안이 없는 신규 배포에서는 이미지 없는 기본 예제를 제공한다. 제작 화면의 **저장된 이미지** 요약과 **저장된 이미지 보기** 버튼에서 갤러리로 이동할 수 있다.


### 제작 파트너 대기·복구

모델이 말하기 전에도 요청 접수와 실제 도구 단계를 표시하고, SSE 연결 유지 신호를8초마다 보내 경과 시간을 갱신합니다. Opus 요청은 최대210초, 개별 MCP 도구는180초, 웹 Lambda는240초로 설정합니다. 검색 완료 출처와 도구가 완성한 수정 제안은 최종 설명 전에 먼저 전송하고 브라우저에 저장합니다. 수정 제안이 완성되면 별도 설명용 모델 라운드 없이 바로 반환합니다. 최종 설명 중 제한 시간에 도달하더라도 완성된 제안은 검토·적용할 수 있습니다. 새 작품의 첫 제안은 항목별600~900자 정도, 총4000자 이내를 목표로 하며, 실제 제작 계획 모델이 세부 장면을 확장합니다. 기존 작품 편집에는 이 분량 목표로 원고를 임의로 축약하지 않습니다. 실패하면 요청문을 복원하고 같은 요청 다시 보내기를 제공합니다. 자동 유료 재시도는 하지 않습니다. 새로고침은 실행 중인 보조 대화 요청을 중단하므로 완성되기 전에는 화면을 유지하세요. 실제 이야기 구성과 GPU 작업은 기존 비동기 작업자가 처리합니다.


### 작품별 제작 이력

초안의 `creatorChatId`가 비공개 제작 대화와 연결됩니다. 초안을 다시 열면 서버에서 전체 대화와 도구·설정 적용 기록을 복원합니다. 브라우저에 남아 있던 과거 대화는 최초 열기 때 이관하며 이미 사라진 과거 대화는 복원할 수 없습니다. 클라우드는 DynamoDB의 소유자별 `creator-chat#` 기록, 로컬은 별도 SQLite에 보관합니다. 제작 이력에는 개인 초안의 임시7일 TTL을 설정하지 않습니다. 모델의 내부 추론 원문은 저장하지 않습니다. 로그인 없는 데모에서는 같은 브라우저의 익명 세션을 기준으로 읽기를 제한하므로 쿠키를 지우거나 다른 브라우저로 옮기면 본인 기록을 자동으로 식별할 수 없습니다.

파트너의 **검색·도구·설정 적용 기록**에서 실행 흐름을 보고, **전체 제작 이력 내려받기**로 모든 대화·제안·실행 입력/결과를 JSON으로 내보냅니다. 현재 입력 폼은 이전 대화보다 우선합니다. 공개 게시·공개 초안 복사에서는 제작 대화 식별자를 제외하고 다른 방문자에게 기록을 제공하지 않습니다.

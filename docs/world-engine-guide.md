# 작품별 세계 엔진 · 2026-11-22

기본 작품 다섯 개와 새 사용자 작품 모두 공통 Graphology 세계 엔진을 사용한다. 작품별 설정은 `world-definitions.ts`, 기존 임사랑 규칙은 `sarang-story.ts`에 있다. 자유 대화는 허용하되 수치·장면 이동·엔딩은 작가가 정의한 행동과 전이 조건으로만 확정한다.

| 작품 | 진행 흐름 | 구성한 엔딩 |
| --- | --- | --- |
| 스타워즈: 아우터 림의 마지막 통신 | 항로 선택·연료 점검 → 출항 → 여섯 척 출항 신호 → 대열 보호 → 합류 확인·인계 | 여섯 개의 응답 / 다른 조종사를 기다리며 / 닫힌 격납고 |

새 사용자 작품은 입력한 세계관을 유지하는 작은 기본 그래프를 받는다. 자유 입력만으로 상세 분기·캐릭터·사건을 자동 설계하는 기능은 아니다. 더 긴 작품은 같은 스키마로 Scene·Action·Counter·Fact·Transition·Ending을 추가하면 된다. 배포 데모에서는 한 회차 최대 24턴이다.

## 대화와 상태가 함께 움직이는 과정

1. API가 회차의 고정된 작품 정의, 현재 상태, 최근 6턴과 근거 기억을 읽는다.
2. 현재 조건에 맞는 작가 작성 추천 문구를 그대로 선택하면 연결된 행동·전이를 코드가 직접 해석한다. 자유 입력은 Haiku가 허용된 행동·전이 중 실제로 해당하는 ID를 최대 2개 고른다. 근거는 서버가 이번 입력 앞 300자에 직접 연결한다. 전체 입력 원문은 해당 턴에 보존하며, 유사한 과거 문구를 모델이 근거로 잘못 복사해 행동이 누락되는 문제를 막는다. 추천의 질문형 후보처럼 행동 연결이 없는 문구도 일반 입력으로 해석한다.
3. 코드가 원문 포함 여부·행동 조건·일회성 여부·숫자 범위·전이 게이트·장면 최소 턴을 검사한다. 같은 턴의 두 행동도 순서대로 조건을 다시 검사하므로 상충하는 편지 개봉·봉인 등을 함께 확정하지 않는다.
4. 확정된 현재 장소·공개 사실·스탯·진행 사건·이번 행동을 선택한 대사 모델에 제공하고 일반 텍스트를 스트리밍한다. 오래된 도입 사실은 현재 상태와 함께 중복 주입하지 않는다. 엔딩 조건을 충족하기 전에는 결말을 확정하지 않도록 지시한다.
5. API가 상태를 코드로 재계산한 뒤 원문·최신 상태·근거 기억을 원자 저장한다. `state.committed` 수신 후 브라우저의 패널과 추천이 같은 확정 버전으로 갱신된다.
6. DynamoDB Streams가 전체 그래프 투영을 비동기로 갱신한다. 다음 대화와 상태창은 이 투영을 기다리지 않고 원장 스냅샷을 사용한다. 로컬은 SQLite WAL과 내구성 있는 투영 작업 큐를 사용한다.

대사에 대한 별도 LLM 재검수·재생성은 없다. 상태와 엔딩은 코드로 제한하지만 생성 모델이 문장으로 설정을 어길 가능성까지 없애는 것은 아니다. 이 데모는 고정된 단계와 선택의 일관성을 다루며 모든 자유 행동을 시뮬레이션하지는 않는다.

## 옆 패널과 추천

데스크톱에는 현재 상태·장소·이야기 시간·현재 목표·스탯·진행 중인 사건·세계관·공개된 사실·최근 변화가 표시된다. 마무리한 사건과 다음 장면의 수치 조건은 펼쳐 볼 수 있다. 작은 화면에서는 상단 상태창 버튼으로 같은 패널을 연다. 미래의 비공개 사실과 전체 작품 정의는 공개 API에 전달하지 않는다.

추천은 별도 LLM 호출 없이 확정 상태에서 계산한다. 장면별 작가 작성 후보 중 조건이 맞는 것만 남기고, 완료한 일회성 행동과 막힌 전이는 제외한다. 진행 가능한 전이와 연결된 행동, 일회성 준비 행동에 우선순위를 주어 최대 3개를 표시한다. 자유 입력은 계속 가능하다. 추천이 사용자의 선택을 대신 확정하지 않는다. 표시한 행동 문구를 그대로 선택한 경우에는 같은 조건을 다시 검사하고 연결된 행동을 직접 실행하므로 입력 해석 LLM 호출도 생략한다. 별도의 의미 매칭으로 비슷한 자유 입력을 버튼 선택처럼 취급하지는 않는다. 이 경로는 원문·확정 사건을 저장하며 별도 기억 추출 호출은 하지 않는다.

시계는 실제 벽시계가 아닌 작품 규칙이다. 스타워즈는 경보 이후 경과 분, 아카데미는 대화 경과와 별도의 D-9, 레코드 바는 중요한 행동마다 1분, 라디오는 턴당 1분을 쓴다. 임사랑은 달력 시각과 명시적 다음 날 전이를 사용한다. 방치한 브라우저의 실제 시간이 이야기를 자동 진행시키지는 않는다.

## 기존 대화

이미 그래프를 가진 회차는 고정된 정의·해시·진행을 유지한다. 임사랑 v2 회차도 현재 표시 항목을 사용할 수 있으며 규칙은 v2로 재계산한다. v3는 새 회차에 사용한다.

그래프가 없던 회차는 기존 메시지와 확인된 신뢰도를 보존하고, 처음 세계 상태를 보는 시점을 표시한다. 조회는 DB를 쓰지 않으며 다음 정상 대화 저장 때 새 정의·상태·추적 시작 턴을 함께 저장한다. 과거 대사를 LLM으로 소급 해석해 출항·접수·공개 송출이 이미 끝났다고 만들지 않는다. 최근 변화의 턴 번호는 전체 대화와 일치한다.

작품별 분기·상충 선택·시한·추천 변화·엔딩·고정 버전·기존 회차의 다음 저장과 재조회는 `tests/scene-world.test.ts`에서 검사한다. 다국어 번역 사전의 DynamoDB 맵 순서가 바뀌어도 작품 해시가 유지되는지, 추천 행동 선택이 LLM 호출 없이 진행되고 지난 행동은 재실행되지 않는지도 검사한다.


## 최종 검증 · 2026-11-22

소스 자동 검사 34개와 독립 배포 ZIP의 검사 27개·빌드·CDK 합성이 통과했다. 최종 공개 배포(`scene-stream/9`)에서 Sonnet 5·Sonnet 5.5·GPT-6 Luna로 7개 흐름, 총 36턴을 실행했다. 기본 다섯 작품과 사용자 작품의 구성된 엔딩, 라디오의 영어 공개 분기와 한국어 비공개 분기를 확인했다. 36턴의 재조회 상태가 응답 상태와 일치했고, 7개 완료 흐름의 비동기 그래프도 마지막 버전까지 수렴했다.

브라우저에서는 스타워즈를 연료 점검 → 직행 선택 → 출항 → 여섯 척 호송으로 진행해 장소·연료·위험·선박 수·사건·추천의 변화를 확인했다. 기존 7턴 보존, 새로고침 복원, 영어·일본어 표시, 작은 화면의 상태창 열기도 확인했다. 모든 모델·모든 자유 입력의 대사 품질을 평가한 결과는 아니다.
